# BizyAir CLI i18n maintenance

BizyAir CLI ships English (`en`) and Simplified Chinese (`zh-CN`) as embedded catalogs. English is the base and fallback language.

The public language-selection rule is `--lang > system language > English`.
The `--lang` option accepts only `en` and `zh-CN`. Automatic detection maps
both Simplified and Traditional Chinese system locales to `zh-CN`; every other
system language falls back to English.

## Adding or changing user-facing text

1. Define a stable semantic message ID in both `internal/i18n/locales/active.en.yaml` and `active.zh-CN.yaml`.
2. Keep the ID set and named template variables identical in both catalogs.
3. Render the message with `i18n.T`, or use `i18n.TN` for plural messages. Do not assemble sentences from translated fragments.
4. Wrap local errors with `i18n.NewError` so their message ID, template data, and cause remain available through `errors.Is` and `errors.As`.
5. Keep command names, option names, configuration keys, protocol fields, URLs, file extensions, model types, and API field names unchanged.

Debug logs and source comments remain technical English and are not catalog entries. Unknown server messages are retained as diagnostic details, while stable server error codes map to local message IDs.

Run these checks before submitting a change:

```bash
go test ./...
go test -race ./...
```

The i18n tests reject duplicate catalog keys, mismatched IDs, mismatched template variables, and hard-coded natural-language text at protected user-output entry points.
